- JS란
  - **JS는 웹에서 동적인 기능과 사용자 상호작용을 가능하게 하는 언어**
  - 특징: 인터프리터 언어, 객체 기반, 동적 타입, 싱글 스레드, 크로스 플랫폼
- JS의 데이터 타입
  - boolean, number, string, null, undefined, object, symbol
  - null vs undefined
    - 둘 다 “값이 없음”을 나타내지만, **의도성과 할당 주체**에서 차이가 있다.
    - `undfined`는 미초기화, `null`은 비어있음
  - symbol
    - 유일한 값이다. 유일한 변수를 선언하기 위해 사용된다.
- 객체
  - **속성과 메서드를 함께 묶은 단위로, 데이터를 표현하고 다루는 핵심적인 개념**
  - JS에서 함수는 일급 객체이다.
    - 변수에 저장할 수 있다(변수의 값으로 할당 가능)
    - 다른 함수의 인자로 전달할 수 있다(콜백 함수)
    - 다른 함수의 반환값으로 사용할 수 있다(고차 함수)
    - 런타임에 생성될 수 있다
    - 익명으로 생성할 수 있다
- 얕은 복사, 깊은 복사
  - 얕은 복사
    - 1차원만 새 객체로 생성, 내부 참조는 주소값 복사
  - 깊은 복사
    - 내부의 모든 중첩 객체까지 완전히 새로운 메모리 공간에 복사
  - JSON 방식의 한계
    - Date 객체는 문자열로 변환될 때 ISO 형식 문자열로 변환되어, parse를 할때 Date 객체로 복원되지 않는다.
    - 함수가 포함되어 있으면 `JSON.stringify()` 과정에서 제거 된다.
    - `undefined`의 경우 `JSON.stringify()` 과정에서 속성 자체가 제거된다.
    - 순환 참조가 있는 객체는 변환 과정에서 오류를 발생시킨다.
    - Map, Set, RegExp 등 내장 객체도 원래 타입으로 복원되지 않고 일반 객체나 빈 객체가 되거나 사라진다.
  - 깊은 복사 방법
    - `structuredClone()` - 최신 브라우저 제공
    - 재귀 함수
    - 라이브러리 사용 - Lodash
- 호이스팅
  - **변수나 함수의 선언 부분이 코드 맨 위로 끌어올려진 것처럼 동작하는 현상**
  - 평가 시간에 의해서 호이스팅 발생
  - JS 엔진은 코드를 2단계로 나누어 처리한다
    - **평가 시간**: 코드를 실행하기 전 JS 엔진이 전체 코드를 훑어보면서 모든 변수 선언과 함수 선언을 찾아 메모리에 미리 등록.
      - 파싱(AST - 추상 구문 트리)과 컴파일(AST 기반으로 바이트 코드로 변환)
      - 변수와 함수의 이름이 스코프에 등록되고 초기화 진행
    - **실행 시간**: 평가 시간이 끝난 후 엔진이 위에서 아래로 코드를 실제로 실행
      - JIT 컴파일 - 자주 반복 실행되는 코드를 백그라운드 컴파일러에 의해 더 빠른 기계어로 최적화 컴파일
  - `var` 호이스팅
    - 선언과 동시에 `undefined`로 자동 초기화
    - 변수가 어디에서 선언되었는지 명확하지 않아 코드의 흐름을 파악하기 어렵게 만든다.
  - `let`, `const` 호이스팅
    - 선언과 실제 변수가 사용 가능한 시점 사이에 일시적 사각지대(TDZ)가 생김
    - 선언 이전에 사용하려고 한다면 ReferenceError가 발생한다.
  - 함수 호이스팅
    - **함수 선언문**은 선언, 정의 모두 스코프 맨 위로 올라가서, 함수가 작성된 위치보다 위에서 호출해도 문제 없다.
    - **함수 표현식**은 함수를 담는 변수만 호이스팅된다.
      - `var`로 선언된 함수는 `undefined`로 초기화 되어 TypeError 발생
      - `let`, `const`로 선언된 함수 표현식은 ReferenceError 발생
- 동등 연산자 & 일치 연산자
  - 동등 연산자 `==`
    - 타입 변환을 허용해 값만 비교
  - 일치 연상자 `===`
    - 타입과 값을 모두 엄격하게 비교
- 스코프 체인
  - 스코프
    - **변수와 함수에 대한 유효 범위 또는 접근 규칙**
    - 변수, 함수는 선언하면 해당 스코프 내에서만 사용할 수 있다.
  - 스코프 체인
    - **스코프들이 계층적으로 연결되어 있는 목록 또는 연결 리스트**
  - 변수 환경
    - 변수 환경은 2가지 주요 요소를 갖는다.
      - **환경 레코드**: 현재 스코프 내의 식벽자와 해당 식별자에 바인딩된 값 저장
      - **외부 렉시켤 환경 참조**: 현재 스코프를 감싸고 있는 렉시컬 환경에 대한 참조를 저장
- this 키워드
  - **함수가 호출될 때 결정되는, 자신을 호출한 객체(context)를 참조하는 키워드**
  - `this` 4가지 바인딩 규칙
    - 기본바인딩
      - 독립적으로 호출될 때, `this`는 전역 객체를 가르 킨다.
      - 브라우저 환경에서는 window 객체
      - Node.js 환경에서는 global 객첵
      - 엄격 모드에서는 `undefined`로 설정된다.
    - 암시적 바인딩
      - 함수가 객체의 속성, 메서드로 호출될 때 적용되는 규칙
      - `this`는 해당 객체 자신을 가리키므로 호출 시점의 마침포(.) 앞의 객체가 된다.
    - 명시적 바인딩
      - `call()`, `apply()`, `bind()`를 이용한 호출은 명시적 바인딩 방식으로 개발자가 함수를 실행할 때
    - new 바인딩
      - 생성자 함수를 new 키워드와 함께 호출할 때 적용된다.
      - 새로운 객체 인스턴스를 생성하고 함수 내부의 `this`는 새로 만들어진 객체에 바인딩한다.
  - 화살표 함수
    - 화실표 함수는 일반 함수와 달리 자신만의 `this` 바인딩을 가지지 않는다.
    - **함수가 선언될 당시의 상위 스코프에 있는 `this`를 정적으로 상속받는다.**
- 실행 컨텍스트
  - JS 코드가 실행되는 데 필요한 모든 환경 정보(변수, 함수, this값 등)을 담고 있는 특별한 객체
  - 실행 컨텍스트 종류
    - **전역 실행 컨텍스트**: 자바스크립트 코드가 실행되는 순간 단 1개 생성
      - 전역 스코프에 선언된 변수나 함수르 포함하고 있다.
      - 전역 객체(window, global)가 this로 바인딩 됨
    - **함수 실행 컨텍스트**: 함수가 호출될 때마다 독립적으로 생성되는 실행 컨텍스트
      - 함수 내부의 지역 변수, 매개 변수, 중첩 함수 등의 정보를 담고있다.
      - 함수 호출 발식에 따라 this값이 동적으로 결정
    - **Eval 실행 컨텍스트**
      - 빌트인 `eval()` 함수에 전달된 문자열 코드가 실행될 때 생성
  - 실행 컨텍스트의 구성 요소
    - **렉시컬 환경**
      - 현재 실행 중인 컨텍스트가 어떤 스코프에 놓여 있는지를 나타내는 구조
      - 환경 레코드
        - 현재 스코프 안에서 선언된 변수, 함수, 매개 변수와 같은 식별자들과 그에 대응하는 값들을 저장
      - 외부 렉시컬 환경 참조
        - 현재 스코프를 감싸고 있는 상위 스코프의 렉시컬 환경을 가리킨다.
        - 스코프 체이닝이 가능하게 한다.
    - **변수 환경**
      - 렉시컬 환경과 거의 동일하지만 ES6 이전 `var` 변수와 같은 초기화 방식의 차이로 별도로 구별 된다.
      - `var` 변수의 선언 정보를 관리하는 역할
    - **this 바인딩**
      - 현재 실행 컨텍스트 내에서 `this` 키워드가 참조할 객체를 결정한다.
  - 실행 컨텍스트의 동작 방식
    - 스택 구조 (실행 컨텍스트 스택, 호출 스택)
- 프로토타입
  - **객체 간에 속성과 메서드를 상속하고 공유하기 위한 또 다른 객체로, 원형 역할을 한다.**
  - `[[Prototype]]` 내부 슬롯과 `__proto__` 접근자 속성
    - 모든 객체는 내부적으로 `[[Prototype]]`이라는 숨겨진 슬롯을 가진다. 해당 객체의 부모 역할을 하는 프로토타입 객체를 참조한다.
    - 직접 `[[Prototype]]`에 접근할 수 없지만 대부분 환경에서 `__proto__`라는 비표준 접근자 속성을 통해 간접적으로 접근할 수 있다.
    - ES6 부터는 `Object.getPrototypeOf()`와 `Object.setPrototypeOf()`가 표준화 되었다.
  - 함수 객체의 prototype 속성
    - 일반 객체와 달리 함수 객체는 특별히 prototype 이라는 공개적인 속성을 가진다.
    - prototype 속성은 해당 함수가 new 키워드와 함께 생성자 함수로 호출될 때 새로 생성되는 객체의 `[[prototype]]` (즉, `__proto__`)으로 연결될 객체를 가리킨다.
- 콜백, 프로미스, async/await
  - 콜백 함수
    - 다른 함수의 인자로 전달되어 특정 이벤트가 발생하거나 비동기 작업이 완료된 후에 호출되는 함수
    - 장단점
      - 장점: 직관적이고 쉽게 적용할 수 있다.
      - 단점: 비동기 작업이 순차적으로 이어질 때, 중첩되면서 코드의 들여쓰기가 깊어지고 가독성이 급격히 떨어진다.
  - 프로미스
    - 성공했는지, 실패했는지를 나중에 알려주는 객체
    - 프로미스의 3가지 상태
      - 대기(pending): 비동기 작업이 아직 완료되지 않은 초기 상태
      - 이행(fulfilled): 비동기 작업이 성공적으로 완료되어 결과를 반환한 상태
      - 거부(rejected): 비동기 작업이 실패하여 오류를 반환한 상태
    - 장단점
      - 장점: `.then()` 체이닝을 통해 흐름을 순차적으로 표현, `.catch()` 하나로 체인 내의 모든 비동기 작업에서 오류를 중앙에서 처리할 수 있다.
      - 단점: 한 번 결정된 상태는 변하지 않는다. 일단 이행되거나 거부되면 상태를 다시 변경할 수 없다.
  - async/await
    - 프로미스를 기반으로 하여 비동기 코드를 마치 동기처럼 보이게 작성할 수 있도록 해준다. (ES8 도입)
    - 장단점
      - 장점: 콜백 지옥과 프로미스 체이닝의 가독석 해결, try…catch 블록을 사용하여 동기 코드처럼 에러 처리 가능
      - 단점: await 키워드는 async 함수 내부에서만 사용할 수 있다. 최상위 스코프에서 바로 await을 사용할 수 없다.
- 이벤트 루프와 태스크 큐
  - 웹 API
    - JS 엔진 자체의 기능이 아니라 브라우저가 제공하는 기능 - setTimeout, fetch, 돔 이벤트 처리
  - 태스크 큐
    - 웹 API에서 처리가 완료된 비동기 작업의 콜백 함수는 바로 실행되지 않고 태스크 큐에서 대기
    - 태스크 큐는 FIFO 구조를 가지고 있음
  - 이벤트 루프
    - 호출 스택과 태스크 큐를 지속적으로 감시하면서 호출 스택이 비어 있는 순간은 포착해 태스크 큐에서 가장 오래 대기한 작업을 하나 꺼내 호출 스택으로 옮긴다.
  - 매크로 태스크 큐 & 마이크로 태스크 큐
    - 태스크 큐는 2가지 종류가 있고, **마이크로 태스크 큐가 더 높은 우선순위를 가지고 있다**
    - 매크로 태스크 큐 - `setTimeout`, `setInterval`, `setImmediate`, `I/O`, UI 렌더링
    - 마이크로 태스크 큐 - `.then()`, `.catch()`, `.finally()`, `queueMicrotask`, `MutationObserver`
- 클로저
  - **함수와 그 함수가 선언될 당시에 렉시컬 환경의 조합**
    - 자신이 만들어질 때의 스코프(변수와 함수에 접근 가능한 유효한 범위)를 기억하는 함수
  - 상태를 안전하게 숨기고(캡슐화) 특정 함수와 연결하기 위해서 사용
  - 장점
    - 데이터 캡슐화 및 정보 은닉, 상태 유지, 독립적인 실행 환경 제공
  - 단점
    - 메모리 소모(누수 위험) `myClousre = null;`
- 이벤트 전파, 이벤트 위임
  - 이벤트 전파
    - **돔 트리에서 이벤트가 발생했을 때 해당 이벤트가 돔 트리의 노드를 따라 이동하는 방식**
      - 캡처링 → 타깃 → 버블링
    - 이벤트 캡처링: 이벤트가 발생한 최상위 부모 요소(window, document)에서 시작하여 실제 이벤트가 발생한 타깃 요소까지 돔 트리를 아래 방향으로 이동하는 과정
    - 이벤트 타깃: 이벤트가 실제로 발생한 요소, 타깃 요소에 도달하는 단계
    - 이벤트 버블링: 타깃 요소에서 이벤트가 처리된 후 다시 돔 트리를 따라 부모 요소 방향으로 이벤트 전파. 키보드 입력 등 대부분의 이벤트가 버블링되지만 focus, blur, scroll과 같은 요소는 버블링 되지 않는다.
  - 이벤트 위임 장점
    - 성능 최적화: 많은 수의 요소에 개별적으로 이벤트 리스너를 등록하지 않고, 하나만 등록할 수 있다.
    - 동적 요소 처리: JS로 돔에 추가되는 요소도 자동으로 이벤트 처리가 적용된다.
    - 코드 유지보수: 이벤트 처리 로직이 한 곳에 집중된다
  - 이벤트 위임 단점
    - `event.target` 검증의 복잡정: 이벤트 핸들러 내부에서 `event.target`이 어떤 요소인지 정확히 확인하고 적절한 로직을 수행해야 한다.
    - 모든 이벤트가 버블링되는 것은 아니다.
- 일반 함수와 화살표 함수의 가장 큰 차이점

  | **구분**                            | **interface**                                        | **type (Type Alias)**                                                         |
