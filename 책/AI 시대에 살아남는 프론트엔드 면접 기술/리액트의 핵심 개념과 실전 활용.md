- 가상 돔과 재조정 과정의 역할
  - 가상돔
    - 실제 돔을 직접 조작하는 작업은 비용이 큰 작업이다.
    - 리액트는 가상 돔이라는 자바스크립트 객체 형태의 가벼운 표현을 돔과 유사한 구조로 만든다.
    - 가상 돔과 실제 돔을 비교해 변경된 부분만 실제 돔에 반영하는 재조정을 통해 돔 조작을 최소화한다.
  - 재조정
    - 리액트가 UI를 효율적으로 업데이트하기 위해 수행하는 핵심 알고리즘
    - 단계
      - 렌더링 발생 → 비교 알고리즘 → 배치 업데이트 → 실제 돔 업데이트
  - 가상 돔과 재조정 과정의 역할
    - 불필요한 실제 돔 조작 최소화
    - 선언적인 UI 작성
    - 플랫폼 독립성 제공
    - 배치 업데이트를 통한 효율적인 렌더링 제공
  - 파이버 객체
    - **컴포넌트 하나에 대한 정보를 담고 있는 JS 객체**
    - 4개의 작업 스케줄을 반복하면서 각 노드의 일을 처리
      - beginWork(): 현재 파이버를 기준으로 자식 파이버를 생성하거나 갱신
      - completeWork(): 자식 파이버들의 처리가 끝난 뒤 호출, 실제 돔 변경을 위한 준비 작업
      - performUnitOfWork(): 하나의 작업 단위 실행하면서 하위 노드 내려가 작업을 이어간다.
      - completeUnitOfWork(): 더 이상 처리할 자식이 없을 때 노드를 올라가면서 작업을 완료하고 형제 파이버로 이동하도록 처리
    - 파이버는 연결 리스트 구조로 이어져 있어 재귀 호출 없이도 전체 컴포넌트 순회가 가능하다.
  - 파이버의 2단계 작동 원리
    - 렌더 단계
      - 리액트가 변경이 필요한 컴포넌트를 파악하여 새로운 파이버 트리를 구축 (work-in-progress tree)
      - 이전 파이버 트리와 새로운 트리를 비교해 어떤 돔 변경이 필요한지 계산 (effect list를 만듬)
      - 비동기적으로 진행되고 필요하면 언제든 중단할 수 있다.
    - 커밋 단계
      - effect list를 가져와 정리된 모든 변경 사항을 실제 돔에 swap 방식으로 한 번에 적용
      - 동기적으로 실행되며 중간에 멈출 수 없다.
- 클래스, 함수형 컴포넌트
  - 2019년 리액트 훅이 등장하기 전까지 함수형 컴포넌트는 상태를 가질 수 없었다.
  - 클래스 컴포넌트는 this.state, 생명주기 메서드, this 바인딩 등이 필요하지만, 함수형 컴포넌트는 훅스를 활용해 더 간결하고 직관적으로 상태와 생명주기를 관리할 수 있다.
- useEffect
  - useEffect 훅은 함수형 컴포넌트에서 렌더링 이후에 실행되는 부수 효과를 처리하는 기능
  - 클래스 컴포넌트의 여러 생명주기 메서드를 하나로 통합한 역할
- 리액트에서 컴포넌트 간 통신을 위해 사용하는 다양한 방법

  | 기본적인 통신방식으로 충분                                                   |

- 리액트 성능 최적화를 위한 방법
  - 메모리제이션 기법
    - 함수의 연산 결과를 저장해 두었다가 같은 입력이 들어오면 다시 계산하지 않고 저장된 값을 재사용하는 기법
  - 컴포넌트 메모이제이션 - React.memo
    - 고차 컴포넌트로, 렌더링 결과가 동일한 컴포넌트를 메모이제이션하여 props가 변경되지 않는한 리렌더링 방지
    - props가 들어오면 얕은 비교를 해서 동일하다면 리렌더링하지 않고 마지막 렌더링 결과 재사용
  - 함수 메모이제이션 - useCallback
    - 처음 렌더링될 때 함수를 생성하고 의존성 배열 값이 변경되지 않았다면 이전에 생성한 함수를 재사용
  - 값 메모이제시션 - useMemo
    - 특정 의존성이 변경되지 않는 한 값을 다시 계산하거나 새로운 참조를 생성하지 않도록 함
  - **앱 로딩 시간 개선**
    - 코드 스플리팅과 지연 로딩
      - 코드 스플리팅은 앱의 모든 코드를 하나의 큰 번들 파일로 만드는 대신 필요한 시점에 필요한 코드만 로딩하도록 번들을 여러 개의 작은 파일로 나누는 기법
      - `React.lazy`와 `Suspense`를 사용하면 컴포넌트가 필요할 때 동적으로 컴포넌트를 로드할 수 있다.
      - `import`구문을 사용하여 특정 모듈을 필요할 때 비동기적으로 가져온다.
  - **이미지 최적화**
    - 적절한 이미지 형식: JPEG(사진), PNG(투명 배경), Webp/AVIF(차세대 포맷, 높은 압축률) 사용
    - 이미지 압축
    - 반응형 이미지: <picture>태그나 srcset 속성을 사용하여 기기 해상도에 맞는 최적의 이미지 제공
    - 지연로딩: loading=”lazy” 속성을 사용하여 이미지가 뷰포트에 들어올 때 까지 로딩 지연
    - CDN: 이미지와 같은 정적 자산을 사용자에게 더 가까운 서버에서 빠르게 전송
  - **번들러 최적화**
    - 트리 셰이킹: 사용되지 않는 코드를 최종 번들에서 제거
    - Minification & Uglification: 코드의 불필요한 공백, 주석 등을 제거하고 변수 이름을 짧게 변경해 파일 크기를 줄인다.
    - 캐싱 전략: 브라우저 캐싱을 활용하여 재방문 시 빠르게 리소스 로드
